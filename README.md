## 这不是简历

简历需要公司名、职位、时间——而这些东西恰恰是最不能公开的信息。

所以这个仓库换了个角度：**不记录"我给谁做过项目"，记录"我解决过哪一类问题，以及我当时是怎么判断的"**。

原因很简单：

> 项目属于公司，判断属于个人。

一个"全渠道订单中台该怎么设计渠道抽象层"的答案，不属于任何一家公司，但能证明我解决过这类问题。

---

## 读者能拿走什么

如果你也是在做系统设计的工程师或技术管理者，这里有三样东西可能对你有用：

1. **技术决策的真实权衡过程**（`01-decisions/`）—— 不是"我们选了 X"，是"我们在 A、B、C 之间怎么选的，以及选完之后发现了什么当初没看到的"
2. **从多个项目里抽出来的可复用模式**（`02-patterns/`）—— 渐进替换的切分维度、多渠道对接的抽象层
3. **一份能直接用的脱敏规程**（`00-DESENSITIZATION.md`）—— 如果你也想公开自己的项目经历又担心泄密，这份分级清单可以省掉你重新摸索的时间

## 写作原则

这个仓库里的每条内容，都按三条硬约束写：

1. **必须写出被放弃的选项。** 只写一个选项的记录不是决策记录，是事后合理化
2. **必须写"当时没看到的"。** 落地后暴露的问题，往往比决策过程本身更有价值
3. **必须给可复用条件，而不是"推荐采用"。** 写清楚什么情况下你会做同样的选择，以及什么情况下它是错的

## 脱敏声明

本仓库所有内容按 [`00-DESENSITIZATION.md`](00-DESENSITIZATION.md) 处理：

- 客户名、雇主名、同事真名 → 行业一级类目与角色代称
- 金额、人天、报价、利润率 → 量级描述或删除
- 漏洞数量、内部系统代号、内部仓库名 → 不出现
- 客户行业 + 精确时间 + 规模的三元可定位组合 → 拆散

完整版台账（含客户名、规模、成本）保存在私有知识库，不进公网。

**如果你在本仓发现任何可能反推到具体公司或个人的内容，请提 issue 或直接告知——这是 bug，不是疏忽。**
