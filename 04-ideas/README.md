# 个人项目创意池

> 从工作里遇到的问题，反推出的**可独立开源的个人项目**。
>
> 这些不是"我想做个什么"，是"这个问题我遇到过至少两次，而且没有好用的现成方案"。

---

## 为什么单独建这个目录

工作里的项目不能公开，但**工作里暴露的问题可以**。

一个在多个项目里反复出现、且没有成熟开源方案的问题，就是一个合格的个人项目选题。它天然具备三个条件：

1. 需求真实（我亲手踩过）
2. 有判断力壁垒（知道坑在哪）
3. 可脱离原项目独立存在（问题本身不属于任何公司）

## 评估标准

一个创意从"想法"变成"立项"，要过三关：

### 1. 我是不是真的踩过

没踩过的选题，写出来的东西没有细节——而细节是唯一不可复制的部分。

### 2. 现成方案差在哪，能不能一句话说清

说不清，说明我还没想明白这个问题，或者说这个问题不存在。

### 3. 脱离原公司后它还成立吗

这是**脱敏的终极检验**。如果答案是否，说明我想做的是"把公司的东西拿出来"，而不是"解决一个通用问题"——那就不该做。

## 与 xingtu-learn 的关系

本目录的创意一旦立项，会同步在 [xingtu-learn](https://github.com/xingtu1996/xingtu-learn) 开一条学习线：

```
工作项目 → 暴露问题 → 本目录登记 → 立项个人项目 → xingtu-learn 开学习线 → 回到本目录更新状态
```

这是"工作驱动学习"的闭环，也是这两个仓互相喂料的方式。

---

## 一个提醒给自己

> 创意池最容易犯的错是**只进不出**。
>
> 每条创意如果三个月没有被推进，应该明确标注"搁置"而不是继续挂着——挂着的状态会制造"我在做很多事"的错觉。
